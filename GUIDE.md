# Вторая лабораторная с нуля

Мы делаем программу «Сводка по городу». Пользователь задаёт город и валюту,
программа получает погоду и курс к рублю из интернета, проверяет ответы,
применяет два правила и выводит сводку. Данные не выдумываются и не зашиты
в код: значения зависят от ответов сервисов в момент запуска.

## 1 Открой проект

В PyCharm выбери File → Open и папку `city_summary` целиком. При открытии
знакомого проекта из своего репозитория можно выбрать Trust Project.
Слева будет дерево файлов; стрелки рядом с папками раскрывают их.

Открой `main.py` двойным нажатием. Это точка входа программы.
`clients` и `processing` — папки с другими частями этого же проекта.
Переход по имени функции в них — обычная навигация к её определению.

Python — программа, исполняющая код. PyCharm — редактор и средство запуска.
Git — история изменений. GitHub — сайт с опубликованным репозиторием.

## 2 Подключи окружение

Открой Settings → Python → Interpreter. Выбери Python 3.12 из `.venv`
этого проекта. На macOS путь заканчивается на `city_summary/.venv/bin/python`.
Окружение из другой лабораторной выбирать не нужно: у этой работы свои зависимости.

На компьютере, где проект подготовлен, окружение уже создано и зависимости
установлены. После скачивания на другой компьютер создай его заново по README.

`.venv` содержит отдельное окружение Python. `requirements.txt` содержит
версии библиотек, нужных для его восстановления. Requests выполняет HTTP-запросы,
Ruff проверяет стиль. Остальные пакеты в requirements — зависимости Requests.
Папки `.venv/` и `venv/` исключены через `.gitignore`.

## 3 Запусти из терминала

В PyCharm открой View → Tool Windows → Terminal. Терминал принимает команды
для запуска программ. Редактор main.py принимает Python-код; команды терминала
не нужно вставлять внутрь main.py.

В корневой папке проекта на macOS:

```bash
source .venv/bin/activate
python --version
python main.py --city Moscow
```

Первая команда включает окружение для этого терминала. Вторая должна показать
Python 3.12.x. Третья запускает программу.

`python` — чем запустить, `main.py` — какой файл, `--city` — имя параметра,
`Moscow` — его значение. Параметры командной строки — это входные данные программы.

Другие варианты:

```bash
python main.py --city Moscow --currency EUR
python main.py --city "New York" --currency USD
python main.py --city Moscow --json
python main.py --help
```

`--currency` выбирает валюту; без него используется USD. `--json` меняет
формат вывода на JSON. `--help` показывает доступные параметры.
Кавычки сохраняют название из нескольких слов как одно значение.

## 4 Запусти зелёной кнопкой

В проект включена конфигурация PyCharm `City_summary`. Выбери её в верхнем
списке рядом с зелёным треугольником и нажми Run. В ней уже указаны параметры
`--city Moscow`.

Для изменения параметров открой Run → Edit Configurations → City_summary.
В поле Script parameters можно поставить `--city Moscow --currency EUR`.
Script path должен указывать на main.py, а Working directory — на корень проекта.

Если запустить Current File без аргументов, программа сообщит, что нужен
`--city`, и завершится с кодом 2. Выбери конфигурацию City_summary или добавь аргументы.

## 5 Прочитай результат

Пример с условными числами:

```text
Город: Moscow
Погода: -3.2°C, ясно
Тёплая одежда: да
USD→RUB: 92.15
Дорогой курс: нет
```

Курс 92.15 означает 92.15 рубля за один доллар. EUR→RUB означал бы число
рублей за одно евро. Температура и курс при твоём запуске могут отличаться.

«Тёплая одежда» — результат правила `температура < 0`.
«Дорогой курс» — результат правила `курс > 100`.
Ровно 0 градусов не включает первое правило; ровно 100 рублей — второе.
Эти пороги — учебные условия обработки данных.

## 6 Проследи путь данных

```text
Команда пользователя
    ↓
main.py — разобрать аргументы
    ↓
processing/service.py — собрать сводку
    ↓
clients/rates.py — получить курс
clients/weather.py — найти координаты города и получить погоду
    ↓
clients/http.py — выполнить GET, обработать статус и разобрать JSON
    ↓
Клиенты проверяют нужные поля и возвращают нормализованные значения
    ↓
processing/preprocessing.py — вычислить два флага
    ↓
main.py — напечатать текст или JSON
```

Для обычной успешной сводки выполняются три GET-запроса: курс, поиск координат,
погода. При временных сбоях запросы могут повторяться.

## 7 Разберись с HTTP и JSON

API — интерфейс, через который программы обращаются друг к другу.
HTTP — протокол запросов и ответов. GET используется здесь для получения данных.
URL указывает адрес ресурса, а параметры запроса уточняют, что именно получить.

REST — архитектурный подход к построению API вокруг ресурсов и стандартной
семантики HTTP. В этой работе мы используем существующие внешние API и их GET-endpoints.

Геокодинг переводит название города в координаты: широту и долготу.
Сервис погоды получает координаты и возвращает погодные данные.

JSON — текстовый формат обмена данными. После разбора JSON-объекта мы получаем
словарь Python. Например, `{"rate": 92.15}` позволяет обратиться к курсу
по ключу `rate`. В JSON пишется `true`, в Python соответствующее значение — `True`.

Успешный статус не доказывает, что содержимое подходит нашей программе.
Нужно проверить структуру и значения ответа.

## 8 Разбери файлы

### main.py

`argparse` читает `--city`, `--currency` и `--json`. Затем вызывается
`build_city_summary`. При успехе результат печатается. При ошибке проекта
сообщение уходит в stderr, а программа возвращает соответствующий код выхода.

`stdout` — поток результата, `stderr` — поток сообщений об ошибках.
Это позволяет получить чистый JSON без примеси текста ошибки.

`raise SystemExit(main())` передаёт возвращённое число операционной системе.
`if __name__ == "__main__"` запускает сценарий при прямом выполнении файла.

### clients/http.py

`get_json` выполняет GET с timeout=8. Проверка статуса идёт до чтения тела
благодаря `stream=True`. Тело успешного ответа разбирается как JSON.
Ответ обязательно закрывается в `finally`.

Timeout — ограничение ожидания соединения или данных в Requests.
Это не общий предел длительности всей программы: есть несколько запросов,
повторы и паузы. Retry — новая попытка после временного сбоя.

Используется три попытки: первая и два повтора. Повторяем Timeout,
ConnectionError, HTTP 500/502/503/504 и 429. Обычно между попытками ждём
1 и 2 секунды. Для 429 учитываем числовой заголовок Retry-After.
Например, `Retry-After: 7` означает подождать 7 секунд перед повтором.

Если получить данные не удалось, наружу выходит исключение проекта.
Остальному коду не нужно импортировать или обрабатывать requests.HTTPError.

### clients/validation.py и клиенты сервисов

Валидация — проверка пригодности данных. Проверяются обязательные поля,
их типы и значения. Температура и курс должны быть конечными числами.
Курс должен быть больше нуля. Координаты должны попадать в допустимые диапазоны.
Валютная пара должна совпадать с запрошенной.

Значения `True`, строки вместо чисел, NaN и Infinity отклоняются.
Это важно, потому что аннотации типов сами не проверяют данные во время запуска.

`weather.py` преобразует внешние названия полей в наши `temp_c` и `description`.
Числовой погодный код переводится в русское описание.
`rates.py` возвращает число рублей за одну единицу валюты и переводит
статусы неизвестной валюты в `CurrencyNotFoundError`.

### processing/preprocessing.py и processing/service.py

В preprocessing находятся два правила. Они принимают уже проверенные числа
и возвращают True/False. Они не делают HTTP-запросов и не печатают текст.

`build_city_summary` вызывает клиентов и объединяет результаты в словарь
с ключами `city`, `weather`, `rates`. К погоде добавляется `warm_clothes`,
к курсу — `expensive`. Саму сводку затем можно напечатать разными способами.

### exceptions.py

Исключение — сигнал об ошибочной ситуации. Все ожидаемые ошибки проекта
наследуются от `CitySummaryError`, поэтому main.py может обработать их
одним `except`. Конкретный класс задаёт причину и код выхода.
`HttpStatusError` — наша собственная ошибка со статусом HTTP.

## 9 Проверь ошибки и тесты

```bash
python main.py
python main.py --city Moscow --currency ZZZ
python main.py --city NoSuchCity8a4d9f1276
```

Первая команда завершится с кодом 2: отсутствует обязательный аргумент.
Вторая при доступном сервисе — с кодом 3: валюта не найдена.
Третья — с кодом 3: город не найден. Ошибки сети после повторов и некорректные
ответы внешнего сервиса дают код 4. Успех — код 0.

Автоматическая проверка:

```bash
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

`unittest.mock` подменяет реальные запросы контролируемыми ответами.
Так можно проверить недоступный сервис, 429, таймаут и неправильный JSON
без отключения интернета и ожидания реальных пауз. В проекте 27 тестов
с дополнительными наборами входных значений.

## 10 Что рассказать на защите

«Я сделала CLI-утилиту для сводки по городу. Она принимает город и валюту,
получает курс у Frankfurter и погоду у Open-Meteo. Для погоды сначала
находятся координаты города. Общая функция get_json отвечает за GET,
таймауты, повторные попытки, статусы и разбор JSON. Ошибки Requests
преобразуются в собственные исключения приложения. Клиенты проверяют
полученные значения и приводят данные к единому виду. Слой processing
добавляет флаги по температуре и курсу и собирает сводку. main.py отвечает
за аргументы, вывод и коды завершения. Дополнительно реализованы JSON-вывод,
аннотации типов и тесты клиентов через unittest.mock».

Для уверенного понимания проследи одну команду `--city Moscow --currency EUR`:
где читается EUR, какой URL получается, где проверяется rate, где вычисляется
expensive и где число печатается. Затем проделай то же для температуры.
