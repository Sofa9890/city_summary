# Сводка по городу

Учебная CLI-утилита получает текущую погоду в городе и курс выбранной валюты
к рублю. Она проверяет ответы внешних API, добавляет два вычисляемых флага
и выводит результат в консоль. Python 3.12.x.

Пошаговое объяснение для начинающего и текст защиты: [GUIDE.md](GUIDE.md).
Репозиторий: https://github.com/Sofa9890/city_summary

## Установка

Откройте терминал в папке `city_summary`.

macOS/Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если окружение уже создано, повторно создавать его не требуется.
В новом терминале его нужно активировать. Версии всех установленных внешних
зависимостей закреплены в `requirements.txt`.

## Запуск

```bash
python main.py --city Moscow
python main.py --city Moscow --currency EUR
python main.py --city "New York" --currency USD --json
python main.py --help
```

Валюта по умолчанию — USD. Коды валют нормализуются в верхний регистр;
для кода требуются три латинские буквы. Название города с пробелами заключайте
в кавычки. Геокодер выбирает первое совпадение; для уточнения можно передать
`--city "Paris, France"`.

Пример вывода (числа иллюстративные; реальные значения меняются):

```text
Город: Moscow
Погода: -3.2°C, ясно
Тёплая одежда: да
USD→RUB: 92.15
Дорогой курс: нет
```

Курс означает число рублей за одну единицу выбранной валюты.
Время обновления данных определяется внешними сервисами.

## Запуск в PyCharm

1. File → Open → выберите папку `city_summary`.
2. В Settings → Python → Interpreter выберите Python 3.12 из `.venv`:
   `.venv/bin/python` на macOS/Linux или `.venv\Scripts\python.exe` на Windows.
3. Откройте `main.py`. В Run → Edit Configurations создайте конфигурацию Python:
   Script path — `main.py`, Script parameters — `--city Moscow`,
   Working directory — корневая папка `city_summary`.
4. Нажмите Run. Для успешного запуска ожидается `exit code 0`.

Включена готовая конфигурация `City_summary` в `.run/City_summary.run.xml`
с параметрами `--city Moscow`. После выбора интерпретатора можно выбрать
эту конфигурацию в верхнем списке и нажать зелёный треугольник.

При запуске без `--city` argparse печатает подсказку и завершает программу
с кодом 2. Это проверка обязательного аргумента.

```text
    ├── test_clients.py
    ├── test_processing.py
    └── test_main.py
```

`main.py` разбирает CLI-аргументы и печатает результат. Клиенты проверяют
ответы сервисов и возвращают нормализованные данные. `processing` собирает
сводку и применяет правила: `temp_c < 0` → `warm_clothes: true`,
`rate_to_rub > 100` → `expensive: true`. Равенство порогу не включает флаг.

Внешние вызовы используют только GET. Погода запрашивается у Open-Meteo:
название города преобразуется в координаты, затем по ним запрашивается
текущая погода. Курс запрашивается у Frankfurter v2. Ключи API не нужны
для выбранных публичных endpoints в учебном некоммерческом сценарии.

## HTTP и ошибки

Вся транспортная логика находится в `clients/http.py`. Функция `get_json`
возвращает JSON-объект Python (`dict`) либо исключение нашего проекта.
Ошибки библиотеки requests перехватываются внутри неё. Клиент курса
обрабатывает собственный `HttpStatusError`, а не `requests.HTTPError`.
Используется `stream=True`: статус проверяется до чтения тела, поэтому
для обработки HTTP-ошибки не нужно ждать загрузки ненужного JSON.
Ошибки соединения при чтении успешного ответа также попадают в retry.

На запрос передаётся `timeout=8`. Это таймаут Requests на подключение и
ожидание данных, а не общий предел длительности всей программы.
Для Timeout, ConnectionError и HTTP 500/502/503/504 выполняются до трёх
попыток: первая и два повтора. Паузы между обычными попытками — 1 и 2 секунды.
Для HTTP 429 числовой `Retry-After` задаёт паузу до следующего запроса;
при отсутствующем или некорректном значении используется обычная пауза.
После третьей неудачи возникает `ServiceUnavailableError`.

Успешный HTTP-статус ещё не гарантирует корректные данные. Проверяются JSON,
тип его корня, структура геокодинга и прогноза, координаты, обязательные поля,
числовые значения и валютная пара. `bool`, NaN, Infinity, отрицательный/нулевой
курс и неизвестный код погоды отклоняются. Валидация выполняется до применения
правил обработки.

| Код выхода | Значение |
| --- | --- |
| 0 | Успех |
| 2 | Неверные или отсутствующие аргументы, пустой город, неверный формат валюты |
| 3 | Город, валюта или запрошенный курс не найдены |
| 4 | Внешний сервис недоступен либо вернул непригодный ответ |

Результат выводится в stdout, сообщения об ошибках — в stderr. Неизвестный
трёхбуквенный код, например ZZZ, преобразуется в ошибку приложения с кодом 3;
для Frankfurter учтены ответы HTTP 400/404/422 этого endpoint.

## Проверки

```bash
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

Тесты используют стандартный `unittest.mock`, не выполняют сетевых запросов
и не ждут настоящих пауз. Проверяются повторные попытки, Retry-After,
преобразование исключений, некорректные внешние данные, граничные значения
правил и коды выхода CLI. Для проверки настоящей сети запустите программу
обычной командой с `--city`.

Дополнительные возможности из задания: `--json`, аннотации типов и тесты
клиентов через `unittest.mock`.
